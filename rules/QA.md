# FlashSight 决策记录（QA，已决议 2026-10-08）

> 本文件是 `rules/addons.md` 定稿的决策来源。决议已全部落入 addons，
> 以后改需求先改 addons，本文件只追加不改写历史。

## 决议一览

- Q1 存储：`<project>/.flashsight` 项目级 + `~/.flashsight` 全局；模型配置会话固化，
  全局只存 provider 连接 + 新建默认值，允许刷新。wasm=本机远程访问，无独立方案。
- Q2 密钥：全局 `~/.flashsight/providers.json` 前期明文（600 权限），TODO 迁系统钥匙串。
- Q3 用量：`usage/calls.jsonl`，append-only 宽字段，每行一次调用。
- Q4 回滚：agent 自维护 patch 栈逆向还原，不污染 git 历史；git 侧栏独立手动回溯；
  非 git 项目自动 init 允许但默认关闭（开关在设置-权限/环境）。
- Q5 rm：直接删除，确认走批准权限门。
- Q6 ask：含 `recommended` 默认选项；自动模式**不下发 ask 工具**；防武断=提示词+高风险
  动作（写/删/发网/跑终端）降级 `deferred`。
- Q7 子代理：只设单会话上限（默认 4），深度上限 3。
- Q8 唤醒：单次时长不设上限+手动取消；项目级可见状态+会话输入框区显示信息；
  中断生成与取消待唤醒共用按钮位、不同图标。
- Q9 过拟合：后端不截断，只在输出块下给截断/折叠提示条；阈值联调再定。
- Q10 标题/summary：先首句截断，≥3 轮或首轮 toolcall≥10 次调摘要模型升级
  （默认继承会话模型）；折叠 summary 靠提示词要求模型自带总结。
- Q11 shell：启动全量探测静默降级（cmd 兜底），设置可显式指定。
- Q12 终端日志：超 10 轮旧日志压缩，默认不删、用户可删，缺文件不报错。
- Q13 环境：全局+项目覆盖，可设忽略全局，设置页显示来源。
- Q14 search：先调研开源实现，有则用，无则接可配 HTTP 搜索 API。
- Q15 套餐：v1 只保能连+计数，`quota` 三态预留；TODO 调研各家（含 opencode 内置）。
- Q16 无 toolUse 模型：创建会话时硬拒绝；供应商虚标则运行时原样透错。
- Q17 path：ghsl filesystem。
- Q18 其余库：httplib(+mbedTLS，远程预留 libssh2，TODO 先验证，不行回退 curl）/
  md4c 魔改 diff AST / nlohmann/json / dtl / git CLI / 自研相似度。
- Q19 i18n/主题：跟随系统，中英先行+翻译渠道（编译预处理进 cpp）；多套配色各含深浅。
- Q20 发送键：默认 Enter 发送。
- Q21 快捷键：v1 只做基础设施，不排默认键。
- Q22 探索/插件：入口保留、灰色不可点；v1 无 `plugin.*`。
- Q23 用量保留：90 天+CSV 导出（用户说随我，已按建议落）。

## 原始问答（备查）

### Q1. 用户数据根目录
A:wasm版只是提供远程访问，具体还是本机。我的建议是`<project>/.flashsight`这样的文件夹，
还有不用存模型单独配置，而是会话固化的设置，允许刷新

### Q2. 密钥存哪
A:存在用户配置文件夹里，`~/.flashsight`前期可以存明文，后期有空了可以改为系统密钥引用，放一个todo

### Q3. 用量库
A:记录每次调用的额度信息，字段不太容易固定，用类似jsonl的格式会更好，甚至yaml嵌套jsonl都可以，
思路如此，具体你来定夺

### Q4. 回滚实现
A:考虑到agent自己维护一套diff系统，那么会话仅文件系统，侧边栏git工具允许手动回溯吧；
非git项目允许自动init，但在设置-权限/环境或其他合适子项设置且默认关闭

### Q5. rm 语义
A:直接删除，至于确认，应该是权限-批准的事了

### Q6. 自动模式 ask
A:A，ask应该让模型给推荐/默认选项并且自动模式ask禁用的意思是不提供此工具

### Q7. 子代理上限
A:单会话上限

### Q8. 唤醒时间
A:B，并且在项目可以看到状态，会话也可以在输入框的地方看到信息
（中断和生成中断可以共用按钮，不共用face）

### Q9. 过拟合阈值
A:过拟合的特征是相似文字重复输出，但不排除本身是格式要求的情况，因此只是在显示的
下面加一个截断而已

### Q10. 标题与 summary
A:我认为一轮对话大部分情况是无法确认主题的，因此设定先用截断，3轮或第一轮模型自主
tool call 10 次后调用模型设置的摘要模型进行摘要，默认继承对话模型；
折叠summary：一轮对话最后的输出，需要提示词显式要求总结

### Q11. shell 降级
A:默认全检测（zsh是我举的例子，意思是linux上bash的替代品）因为有cmd保证一定可用，
因此不直接提示，但用户可用去设置显式指定

### Q12. 终端日志
A:对过早的调用（10轮以前）启用压缩，默认不删除，但允许用户自主删除
（即文件不存在不会引发错误）

### Q13. 环境覆盖
A:全局，对于项目单独设置，会进行覆盖，可设置忽略全局

### Q14. search 选型
A:如果有开源实现可用直接用，没有就先按A来

### Q15. 套餐深度
A:A，重点调研各家套餐需要的功能，后面可用使用字段直接定义多家（比如opencode内置了很多）

### Q16. 不支持 toolUse 的模型
A:不支持toolUse的模型大概也不适合做agent工作，直接拒绝。或者说默认支持，
调用后因不支持而报错不归工具管

### Q18. 第三方库
httplib/mongogoose+libssh2+mbedtls会不会更好？
md4c非常轻量，因为支持增量解析的只有tree-sitter过于重了，可用选择魔改md4c
（正好输出diff ast符合项目要求）

### Q19. i18n/主题
A:跟随系统，可自己设置。语言提供中英和翻译渠道（比如单独文件，编译时预处理进cpp文件）
主题提供多种（不同配色但都有深浅色，WhaleUI支持css@media查询）

### Q21. 快捷键
A:先做好支持基础，不急着上来就搞（因为确实有人平常用不上）

### Q22. 探索/插件页
A:按钮灰色按不了就行

### Q23. 用量保留
A:随你
